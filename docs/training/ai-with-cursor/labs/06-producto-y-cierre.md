## Antes de empezar

- [ ] Historia de sesiones 3–5 merged, en PR o bloqueada (anótalo en workbook).
- [ ] No tienes carpetas copiadas de otro producto (`SML-*`, `runtime/` ajeno, etc.).

---

## Pasos

### 1. Copia scaffold de company (vacío)

`cursor/company/`, `future-work/`, regla `company-product-context.mdc` si aplica.

**Verifica:** no hay IDs ni paths de otro repo vivo.

### 2. Borrador de visión — Ask

Modo explorar. Pide borrador de `product-vision.md` (inglés, **máx. una página**).

**Verifica:** **tú** recortaste features que el equipo no planea — el modelo inventa a veces.

### 3. Escribe tres ítems `FW-<PREFIJO>-*`

Deuda, feature futura, riesgo — una frase cada uno. Distintos del ticket Jira/GitHub de esta semana.

**Verifica:** tu lead (o tú) valida que al menos uno es real, no relleno.

### 4. Completa workbook sesiones 1–6

[participant-workbook.md](../participant-workbook.md): capas 0, A, B; checklist operativo; prompt de intake listo para copiar.

**Verifica:** workbook entero marcado.

### 5. Repasa checklist operativo (juntos o solo)

Desde el runbook / workbook:

1. No abras el agente sin mapa o feature activa.
2. Historia nueva → intake primero.
3. Verify con **tu** comando.
4. Si pide leer todo el repo → recorta scope.
5. Kit desde template, no clonar otro producto.

**Verifica:** puedes pegar intake y bug-fix sin leer el playbook entero.

### 6. (Opcional) Mira scripts Layer C

Existen; no son obligatorios en el curso (C27).

## Listo cuando — cierre del **programa**

- [ ] Capa 0 en el repo (mapa + reglas).

- [ ] Visión de una página + 3× `FW-*`.
- [ ] Workbook completo (sesiones 1–6).
- [ ] Nadie trajo Capa D de otro producto.
